# F&C Design System — 受け渡しガイド

このzipを他システムのUI/UX設計に使うときの手順。

## 1. 何が入っているか
| フォルダ | 中身 | 他システムで使うか |
|---|---|---|
| `styles.css` + `tokens/` | 色・文字・余白・角丸・影・動きの定義 | **必須**。これだけで見た目がF&Cになる |
| `components/` | 27個の再利用コンポーネント（`.jsx` + `.d.ts` + `.prompt.md`） | **必須** |
| `guidelines/` | 18枚の作法カード（禁止例つき） | 判断に迷ったとき見る |
| `ui_kits/` | 3視点の実装例（スタッフ/店長/本社） | 組み方の参考 |
| `readme.md` | デザインシステムの正典。言葉の作り方・色の3原則・追加部品の理由 | **最初に読む** |
| `SKILL.md` | AIエージェント用の入口 | AIに使わせるなら必須 |
| `pkg/` | 支給元資料（要件定義・仕様・画面モック） | 出典確認用 |
| `F&C Portal.dc.html` | HR HUB 全63画面のプロトタイプ | UXの実例集 |
| `assets/` | 空（ロゴ・フォント未支給） | 支給されたらここへ |

## 2. 新しいプロジェクトでの使い方

### AIに設計させる場合
zipを展開し、`SKILL.md` と `readme.md` を読ませる。それだけで色・言葉・部品の作法が伝わります。

### 人が実装する場合
```html
<link rel="stylesheet" href="./styles.css">
```
これ1行でトークンが全て入ります。あとは `components/<グループ>/<Name>.jsx` をコピーして使う。各コンポーネントに `.prompt.md`（使い方と実例）が付いています。

## 3. 他システムに広げるとき守ること（これを外すとF&Cに見えない）
1. **色面の文字は同じ色相の濃淡で書く。白文字は使わない。**
2. **各インクは対応する色面の上だけ。白地の強調は `Badge` / `MetricPill` に載せる。**
3. **Wasabi（#E9F056）は作業エリアに1点だけ。**
4. 影は画面の外枠1箇所のみ。中身は線で区切る。
5. 一覧は1行=1件の密な表。状態は列に固定する。

## 4. HR HUB 以外のHUBに使うとき
Retail Hub / MD Hub / FIN Hub も同じトークンと部品で組めます。視点ごとの端末の考え方（店舗スタッフ=スマホ／管理=PC）と、サイドバーの階層ルール（項目15超で2階層）はそのまま流用してください。

HUB固有で足りない部品が出たら、`readme.md` の「Intentional additions」と同じ形式で**追加した理由を1行書いて**から足す運用にすると、システムが濁りません。
