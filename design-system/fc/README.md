# F&C Design System

株式会社 Food & Company（F&C）の社内業務ポータル **F&C Portal** と、その中の人事システム **HR HUB** のためのデザインシステム。HR HUB のプロトタイプ（全63画面）で実証済みの UI/UX を、そのまま再利用できる形に落とし込んだもの。

- 全HUB共通の低レベル基盤（色・文字・余白・角丸・影・動き）
- 27個の再利用コンポーネント（`components/`）
- 3視点のUIキット（`ui_kits/`）— スタッフ（スマホ）／店長（PC）／本社・人事（PC）
- 使い方の作法カード（`guidelines/`）

## 出典（このシステムを作った元資料）
すべてユーザー支給。リンクではなくファイルとして `pkg/` と `uploads/` に保存済み。

| 資料 | 役割 |
|---|---|
| `pkg/fc-design-system-v2.html` | **正本**。基本5色＋派生12色、文字、ボタン、バッジ、表、ダーク面、ファイルタブ、ルール12項目（D73〜D80） |
| `pkg/fc-design-handoff-v2.md` | 引き継ぎパッケージ v2（要件定義書 v4.5 / D1〜D103 の抜粋、63画面のサイト構成） |
| `pkg/fc-impl-spec-*.md` | 機能別の実装仕様（勤怠・評価・法令対応ほか） |
| `pkg/fc-hrhub-*-screens-v*.html` | 画面モック（ホーム／承認／組織図 v6／管理／法令対応 ほか） |
| `F&C Portal.dc.html` | このプロジェクトで作った全63画面のプロトタイプ。**UXの正本** |

コードベース・Figma・GitHub の接続はなし（支給されていない）。

## 製品の文脈
F&C Portal は業務ごとの「HUB」を束ねる社内ポータル。HUB は **HR HUB**（人事）、Retail Hub（店舗運営）、MD Hub（商品）、FIN Hub（経理・準備中）。

HR HUB の利用者は3視点で、必要な画面と端末がまったく違う。

| 視点 | 端末 | 画面数 | 中心にあるもの |
|---|---|---|---|
| スタッフ（店舗） | **スマホ** | 22 | 今日のシフト・打刻・申請。1分で終わることが価値 |
| 店長 | PC | 7 | 承認・シフト作成・勤怠。**判断材料 → 操作**の順が価値 |
| 本社・人事 | PC | 30 | 法令対応・制度・全社分析。**一覧性**が価値 |

店舗スタッフがスマホで使うため、**モバイルファースト**が全体の前提。

# CONTENT FUNDAMENTALS（言葉の作り方）

## 話し方
- **やさしい日本語**。漢語を避け、動詞で言う。「要修正」→「直してください」、「未達」→「あと3日」。
- **一人称は使わない。相手は「あなた」**。「山田さんの申請」ではなく画面上は「あなたの申請」。
- **敬語は「です・ます」の平体**。「〜いただけますでしょうか」のような二重敬語は使わない。
- **命令ではなく行動を示す**。ボタンは「送信」ではなく「この内容で申請する」。
- **絵文字は使わない**。例外は権限の錠 🔒 と、サンクスの星 ★ だけ（このシステムでの固定記号）。

## 具体例（プロトタイプの実文）
| 場面 | ✓ このシステムの書き方 | ✗ 避ける書き方 |
|---|---|---|
| 主要ボタン | この申請を承認する / この週を公開 / 8月度を締めて人事に送る | 承認 / 公開 / 締め処理 |
| 期限 | 期限 残り1日（要対応） | 期限切迫 |
| 空状態 | 未処理の申請はありません。新しい申請が届くとここに並びます。 | データがありません |
| エラー | 「@」以降を確認してください。 | メールアドレスの形式が不正です |
| 差し戻し | 何を直せば承認できるかを具体的に書いてください | 却下理由を入力 |
| 権限 | 機微情報（雇用条件・書類・遍歴）は人事のみ表示 🔒 | アクセス権限がありません |
| 伏せた集計 | 5名未満の単位は個人が特定できるため、集計値を伏せています。 | （何も書かない） |
| グラフの読み方 | バーの黒線＝義務の5日 / 右端の黒線＝予算 ¥530,000 | （凡例なし） |

## 数字の書き方
- 単位は必ず付ける（`7 / 12日`、`41h`、`¥530,000`、`46日`）。
- 比率は分母を見せる（`8 / 10名`、`2/3 不足`）。裸の%は使わない。
- 状態は数と語をペアにする（`3名 要対応`）。色だけ・数字だけにしない。
- 日付は `9/20（金）`（画面内）と `2026/09/20`（台帳・帳票）を使い分ける。

## 見出しの作り方
画面名は機能名ではなく**そこで何を見るか**。「有給管理」ではなく「有給5日取得の進捗」。見出しの下の1行（`ScreenHeader.meta`）に必ず「対象・件数・読み方」を書く。

# VISUAL FOUNDATIONS

## 設計の核: 2層構造
濃い **Cassis 面のナビ** ＋ **白い作業エリア**。濃い面はナビだけに使い、作業は必ず白地で行う。スマホではサイドバーの代わりに Cassis のヘッダーとボトムナビが同じ役割を担う。

## 色（`tokens/colors.css`）
出発点は**基本5色のみ**。派生は12色で固定し、それ以外は作らない。

| 色 | 値 | 役割 |
|---|---|---|
| Wasabi | `#E9F056` | 「今ここ・次にやること」。主要ボタン・選択中・今日・現在値のバー |
| Orange Topaze | `#FF5C34` | 緊急・期限・エラーのみ。塗り面には使わず枠線とバーに使う |
| Cool Blue | `#D7EFFF` | データの面・顔アイコン・過去のバー |
| Cassis | `#351E28` | ナビの面・本文・基準線 |
| Vert Sauge | `#AEB8A0` | 罫線と無効状態のみ（大面積では使わない） |

派生12色: Orange Tint `#FFD8C2` / BG `#EFEFEA` / Card `#FFFFFF` / Row `#FBFAF6` / Line `#E2E1DA` / Ink Soft `#84787D` / Wasabi Ink `#666C14` / Blue Ink `#33566F` / Orange Ink `#B03616` / Sauge Ink `#4C5544` / Cassis Tint `#C9A2B8` / Cassis Soft `#9C8290`。

### 色の使い方（このシステムで最も重要な3つ）
1. **色面の文字は同じ色相の濃淡で書く**。Wasabi面→Wasabi Ink、Cool Blue面→Blue Ink、Orange Tint面→Orange Ink、Cassis面→Cassis Tint、Sauge面→Sauge Ink。**白文字は一切使わない**。
2. **各インクは対応する色面の上でしか使わない**。白地に Orange Ink や Blue Ink を直置きしない。白地で強調したいときは `Badge` / `MetricPill` に載せる。
3. **Wasabi は1画面1点**。数えるのは作業エリアの Wasabi（主要ボタン／NoteCard／現在値のバー）で合計2点まで。`BrandPill` と選択中のサイドバー項目は固定要素として数えない。

### カードの色分け（D79）
- **数値・データ → Cool Blue**（`DataCard`）
- **ひとこと・説明・AIのきづき → Wasabi**（`NoteCard`）
- **期限・要対応 → Orange Tint**（`AlertBanner` / `DataTable` の `alert` 行）

読む前に「データか、ひとことか」が形と色で分かる。

### グラフ（D78）
塗り面ではなく**線と細いバーで構成**する。過去=Cool Blue / 現在=Wasabi / 警告=Orange / 基準線=Cassis の2px線。組織図・マトリクスの箱も塗らず線で描く。

## 文字（`tokens/typography.css`）
`font-family: "Manrope", "M PLUS 2", sans-serif` の**指定順**で、英数は Manrope、かなカナ漢字は M PLUS 2 が自動で当たる。

サイズは5段だけ: 21px/800（画面タイトル）・15px/700（セクション）・14px/400（本文）・12.5px（補助・表）・11px（バッジ・注釈）。主要な数値は 24px/800。数字は常に `font-variant-numeric: tabular-nums`（`.fc-num`）で桁を揃える。`font-feature-settings:"palt"` を body に当て、日本語の詰めを効かせる。

## 余白（`tokens/spacing.css`）
**8pxの倍数のみ**（4pxは半歩としてのみ）。カード内=16px、セクション間=24px、画面の左右=26px。スマホのタップ対象は **44px以上**（`--fc-tap-min`）。

## 角丸（`tokens/radius.css`）— 形で役割が分かる
ピル `999px`=操作（ボタン・バッジ・チップ）／`16px`=カード・リスト行・表／`12px`=入力欄・メニュー項目／`24px`=画面の外枠・サイドバー。ファイルタブは上2角だけ `12px`、パネルは左上を除く3角 `16px`。

## 影（`tokens/elevation.css`）
**影は画面の外枠1箇所のみ** `0 20px 50px rgba(53,30,40,.12)`。中身は線（`--fc-line`）で区切る。カードを浮かせない。

## 背景
写真・イラスト・グラデーション・テクスチャは**使わない**。背景は無地（BG / Card / Row の3段）だけ。全ブリードの画像もない。透明度とぼかしも使わない（唯一の例外は Cool Blue 面上の `rgba(255,255,255,.55)` のタイル）。

## 動き（`tokens/motion.css`）
控えめ。120–180ms / `cubic-bezier(.2,.6,.3,1)` で**色と不透明度だけ**を変える。拡大・縮小・跳ね・スライドインは使わない。

- **ホバー**: ボタンは `filter: brightness(.96)`（暗くする）。表の行は背景を Row に。
- **押下**: 色だけ。位置・大きさは変えない。
- **フォーカス**: `outline: 2px solid Cassis / offset 2px`。入力欄は Cassis 枠 ＋ Wasabi の薄いリング `0 0 0 3px rgba(233,240,86,.5)`。
- **無効**: 面=BG、文字=Sauge、枠=Line、`cursor: not-allowed`。

## 境界とレイアウトの決めごと
枠線は常に1pxの `--fc-line`。強調枠は Cassis 1px（選択中）、警告枠は Orange 1.5px。固定要素はサイドバー（236px固定）とスマホのボトムナビだけ。作業エリアはスクロール、見出し帯は固定しない。フレームはスマホ390×844 / PC1240×830 の固定寸法で、それ以外（カード・表）は伸縮する。

## チェックボックス・ラジオ
`accent-color: var(--fc-cassis)` で必ず染める。ブラウザ標準の青が混ざるのを防ぐ。

# ICONOGRAPHY

**このブランドはアイコンをほぼ使わない。** 支給資料にアイコンフォント・SVGセット・スプライトは含まれていなかったため、システム側でも**アイコンセットを導入していない**（CDNの代替も入れていない）。代わりに以下で意味を伝える。

| 代わりに使うもの | 例 |
|---|---|
| **語そのもの**（最優先） | 「承認する」「差し戻す」「取得を案内」 |
| **状態バッジ** | 新着 / 確認中 / 承認待ち / 期限間近 / 下書き |
| **色面** | Cool Blue=データ、Wasabi=ひとこと、Orange Tint=期限 |
| **顔アイコン**（姓1文字） | `FaceAvatar`。写真は未支給のため文字で代用 |
| **細い矢印** | 一覧の行末 `→`、戻る `←`（テキスト文字） |
| **絵文字2つだけ** | 🔒（権限で伏せた項目）・★（サンクス／店長） |

`IconButton` は40pxの丸い器だけを提供し、中身のグリフは呼び出し側が渡す（現状は `✓` `💬` のような文字を入れている）。

## ロゴ
**ロゴ画像は支給されていない。** したがって描き起こしも再現もしていない。ブランド表記はすべて `BrandPill`（Wasabi面に「F&C Portal」の文字ピル、`letter-spacing:.04em`）で代用している。**本物のロゴファイルがあれば差し替えたい**（`assets/` に置いて `BrandPill` を書き換える）。`assets/` は現在空。

# Intentional additions（正本にない、プロトタイプから抽出した部品）

`pkg/fc-design-system-v2.html` が定義していたのは Button / IconButton / Input / Field / Badge / Card / DataCard(cardB blue) / NoteCard(cardB yellow) / DataTable / Sidebar項目 / NoticeRow / FileTabs / FilterChip の13種。以下は**63画面のプロトタイプで繰り返し必要になった**ため追加した。それぞれ理由つき。

| 追加 | 理由 |
|---|---|
| `BaselineBar` | 「予算」「義務5日」など基準線つきのバーが法令・シフト・評価の6画面に登場した |
| `MetricPill` | ルール4（白地にインク直置き禁止）を守るには、表の中の数値を載せる面が必要だった |
| `KVTable` | 申請内容・台帳の「項目: 値」が20画面以上で同じ形だった |
| `FaceAvatar` | D78で顔アイコンの色が指定されており、組織図・一覧・ヘッダーで共通化が必要 |
| `StatBand` | 管理画面の1行要約が11画面で同形 |
| `AlertBanner` | 期限告知（未提出・締め停止）が5画面 |
| `Sidebar` / `UserChip` | 正本はリスト項目のスタイルのみ定義。3階層・バッジ・本人表示を含む器が必要だった |
| `BottomNav` | モバイルファーストの要件に対し、正本にスマホのナビ定義がなかった |
| `ScreenHeader` / `MobileHeader` | 「見出し＋対象＋読み方＋絞り込み」の組が全管理画面で同形 |
| `EmptyState` / `LockNotice` | 空状態と権限非表示の書き方が製品の信頼性に直結するため、文章ごと部品化した |
| `Textarea` / `Select` / `Checkbox` / `Radio` | 正本はテキスト入力のみ定義。申請フォームに必要 |
