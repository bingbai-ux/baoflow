# 全ページUI整理 — 2026-10-01

基点: 公開済み `6ab0c287dc941d394bbbcf56ecc43f617e08db63`。作業ブランチ: `codex/ui-clarity-all-pages`。
DB・RLS・RPC・権限・メール設定を変更しない。実案件を操作せず、画面記録と操作検証にはlocalhostの合成データを使用する。

## 設計と変更

- 案件: 上部の状況欄を圧縮し、スマホの13工程を1つの選択欄に整理。工程の欠けている内容をスマホでも表示し、主操作を画面内へ近づける。工程切替は閲覧であることをボタン名で区別し、URL・再読込・戻るに対応。工程の番号と名称で同じ操作を二重にフォーカスさせない。
- 在庫・各ポータル: 表示中のタブをURLに保持。44px操作領域、選択状態の読み上げ、明確な作業名を共通化。顧客の「発注」は実処理に合わせ「出荷依頼」へ変更。物流では承認済みの出荷可能数と営業確認待ちを別表示し、待ち理由を依頼内にも表示。
- 保管請求: 発行済み履歴と作成入口を優先し、長い入力は作成を選んだ後に開く。参考の現在庫概算・単価設定・証明書は開閉式の補助情報へ移動。入力を3群に分け、発行を解除するための不足入力・確認条件をボタン近くへ表示。保存後はPDF確認を案内。読込中・取得失敗・履歴なしを区別する。
- 帳票・請求・在庫・出荷依頼: 検索と解除操作を追加。帳票はスマホで読める行カードと種別絞り込みへ変更。表が必要な台帳はカード内で横スクロールし、ページ全体をはみ出させない。
- 工場: 未回答RFQを発注閲覧より上に配置。返信操作を主操作にする。期限と担当先の情報は既存の実データのみを使用。
- 共通: スマホの社内ヘッダーを1行へ整理し、通貨変更を選択欄として維持。外部ヘッダーの折返しとログアウト中・失敗表示、本文移動、認証の入力ラベルを修正。取得失敗を0件として出す画面を再読込導線へ修正。設定の登録リンク管理は補助領域へ移動。
- メール: サーバーが既存設定の有無だけをbooleanで渡す。秘密値はブラウザへ渡さない。設定がない場合は送信を無効化し、PDF／回答リンク共有と管理者への依頼を表示。受理済み・結果不明の請求書へ新たな送信入口を出さない。これは本番メール到達の検証ではない。

F&Cの色・フォント・形・既存データモデルを維持。単に全画面へ説明バナーを追加せず、操作の重複と補助情報の優先度を整理する。担当や期限がデータとして存在しない一覧には架空の値を付けない。

## 証拠と検証境界

- `tmp/ui-clarity/before/`: 公開版と同じコードをlocalhostで実表示した8画面×1280/390px、16枚。
- `tmp/ui-clarity/after/`: 同じ合成データ・同じ画面幅で変更後を記録。
- `tmp/ui-clarity/routes/`: 全ルート・タブの画面記録76枚。これらは本番スクリーンショットではない。
- `tests/e2e/ui-clarity.spec.ts`: 全ルートのHTTP200・表示エラーなし・ページ幅はみ出しなし、タブ／工程の再読込と戻る、主操作の画面内表示、検索解除、物流承認待ちの操作不在を検証。
- 最終ブラウザ全回帰32件合格（1 worker、2.7分）。選択欄の名前解決で検出したタイムアウトは明示的なラベルで修正し、再検証合格。取得失敗時の再読込もホーム・分析・履歴・アカウント管理で検証。
- ソース全体101テスト、数量／採用／wizardの3検証スクリプト合格。最終lint・型チェック・production build合格。
- `artifacts/ui-clarity/` に5画面の変更前後10枚を保存し、目視確認。スマホ案件の主操作が740pxより上にあることを実測して検証。操作数の削減率は未計測。
- ブラウザfixtureは表示・アプリのルート／アクション接続用であり、本番RLSの証明にはならない。旧実DB／Mailpit検証と今回のUI回帰を混同しない。
- Macの既存ログインブラウザを操作するツールは今回提供されていない。本番の認証済み実画面の追加撮影は未実施。
