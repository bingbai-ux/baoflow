# 第7段：発送・中国物流・食品条件・追跡・顧客受領・納品書

候補 `20261001145000_shipment_workflow_v1.sql`。本番未適用。既存BAO倉庫入庫のinbound_shipmentsを輸出台帳へ流用しない。実発送/実振込/実取引先メールなし。

## 実装と入力の境界

営業 `/deals/:id/shipping`、工場 `/factory/orders/:orderId/shipping`、担当物流 `/logistics/shipments/:orderId`、顧客 `/portal/shipments/:orderId`。営業がQC/必要支払を確認し、発注内の数量・船便/航空便・食品要否の確認根拠・登録配送業者・既存物流アカウントの本人/所属・中国受取先出典・最終住所/受取人/電話を固定する。分便の計画合計は発注数量まで。新しい認証情報/招待は作らない。

納品住所は注文商品保存値、顧客既定値、今回の確認済み自由住所を区別し、保存元を再照合する。後からマスターを変えても保存版を変えない。倉庫保管は今回選択不可、既存倉庫機能は保持。中国受取先は正式な船/air×食品宛先対応表が未取得のため自動割当しない。空住所・空出典・未確認条件では保存不可。

工場だけが実中国国内発送を記録。担当に指定した物流本人だけが中国受領→食品検査/届出準備→通過確認→国際輸送出発→日本到着→顧客配送→配送会社配達を記録する。食品不要は営業の明示確認根拠が必要で、検査2段だけを飛ばす。食品要では飛ばせない。各状態は追跡識別子/情報源/実発生時刻/確認内容/確認チェックを持つ。未来・計画前・時系列逆転を拒否し、同時刻でも工程順を保つ。

外部追跡API・FAINS・検査機関へ接続しない。「追跡API未連携・手動確認」と表示。到着予定日は未確認と表示し物流への確認を促す。生の情報源は顧客に公開しない。

顧客本人だけが自社便の実受領数量・日付を記録し、一部受領後は残数を表示する。未受領なら記録せず営業へ連絡する導線。配送報告では受領を自動作成しない。期待既受領数量を照合して古い画面の二重受領を拒否。全便・全発注の実発送で営業がshippedへ、全顧客受領・納品書・納品書メール受付が揃って営業がdeliveredへ明示反映する。直接status変更も同条件でguard。旧新台帳なし案件にはbackfillしない。

納品書は顧客全受領済みの便単位固定版。商品名・数量・受領日・納品先・発注番号・発行者を含み、工場単価/銀行情報を含めない。営業と自社顧客だけがPDFを取得可能。配送通知（工場発送時は登録配送業者、他は登録顧客）と納品書添付送付は営業が宛先/内容をプレビューして確定。永続送信予約がある通知は、受付/拒否/応答不明/結果保存失敗を問わず自動再POSTしない。受付≠到達。ローカル検証先はMailpitのみ。

画面は現在・待ち・担当・次操作、数量、食品条件を先頭に整理。住所根拠/輸送履歴を折畳み、役割に応じる操作のみ表示する。更新中は再操作を抑え、UUID/SHAのみ保存して再読込で本人の保存結果を復帰する。

- 物流：営業が当該便へ指定した既存logistics本人のみ、配送先/数量/手動履歴を読取、国内受領以降の実輸送/食品工程をwrite。別担当の便・顧客受領・納品書PDF・メール管理不可。
