## 復旧方針

既存の依頼・回答・6件の旧見積を変更/推測補完しない。新依頼は新RFQ番号を持ち、旧依頼を自動失効させない。親RFQ・改訂番号の専用列は今回追加しておらず、番号別の履歴として保持する。

v2回答リンクを発行した後にアプリ全体を旧版へ戻すと、旧UIが数量別回答を作れなくなる。単純な旧版全面ロールバックは不可。障害時はv2の新規作成・送信を止め、互換の外部回答画面とDB関数を残す修正版へロールフォワードする。保存済みsnapshot/回答/receiptを削除・リセットしない。外部送信の不明/拒否状態は自動解除しない。

本番適用前に最新の復元点・適用後書込の扱いを再確認する。新しいローカル本番export、課金、外部テストメールは実施しない。localhost合成DB・Mailpitの実接続と最終tested commitを確認してから公開する。
