次の提出・不承認後の再提出には、前版と違う実ファイルSHAを最低1件要求する。別UUIDで同じ不承認ファイルを再登録しただけでは新証跡扱いにしない。全体・梱包写真と動画、実完工日、累計数量、工場確認、営業の最新版確認は必要。server actionの実bytes/hash/形式確認と非公開readは維持。

不承認は既存 factory_qc_reviews に rejection_scope（all / new_quantity、既定all）を追記する。影響が不明、または既承認分にも問題がある場合はallで新発送を停止し、修正証跡が承認されるまで承認容量を0とする。営業が追加分だけの不承認で既承認分に問題なしと明示確認した場合だけ、前の承認数量を維持する。発送済み品の回収/返品は未実装の専用訂正・連絡へ残す。

承認容量を shipment_plans と有効 inbound_shipment_items の合計で共用する。未承認量の計画、配送/倉庫の二重割当、倉庫予定取消後に別便へ使った数量の再有効化を拒否する。発注行のロック後にvolatileの予約量照会を行い、同時割当で古いsnapshotを再利用しない。旧製造開始台帳なし案件は新しいQC事実を推測登録しない。

工場の発送前残金条件は分納でも合意済み総額のまま。按分の推測はしない。顧客発送前条件も第8段の独立gateで確認。全便の実発送前に案件をshippedへ進めず、全受領/納品書/送付受付前にdeliveredへ進めない。倉庫保管請求の新拡張は本段に混ぜない。

画面はQC承認累計・配送/倉庫割当・未割当容量を表示。承認分を割当済みなら工場の次の累計提出へ、営業配送画面から製造/QCへ戻れる。物流/顧客へQC画像・銀行情報を追加公開しない。
