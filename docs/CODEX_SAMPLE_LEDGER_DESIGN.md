# サンプル独立手配・後日まとめ請求：実装契約

2026-10-01。実装前設計。基点0d9af18。最新確定要件はCODEX_CASE_FLOW_REQUIREMENTS_20261001.md。既存deal_samples/deal_sample_summaryは閲覧保持し、推測移行しない。本書は機能完成・本番権限承認を示さない。

## 確認した既存実装の不足

現役の独立サンプル画面はなく、legacy samples actionのみ。既存表は案件・round・製作費/送料/版代USD・小計・状態を保持するが、商品/仕様参照、概算と確定実費、工場支払記録、費目ごとの請求割当がない。legacy actionは空欄を0へ変換し、FX未取得時155を使い、max(round)+1で並行作成が競合する。この処理を新導線へ再接続しない。

## 業務と画面

案件内の独立作業面。上部にround・対象商品/仕様・担当/期限・現在状態・次の作業。量産見積の採用や顧客前払は手配条件にしない。1回目/2回目を別記録にし、同じ商品でも前回内容を上書きしない。

製作費・版代・UPS/FedEx送料は別費目。概算、確定実費、顧客負担額、工場支払記録を区別。配送accountやBAOサービス費は未確定契約を推測追加しない。通貨/為替/税の未確認値は空欄と不足理由を表示し、請求確定を停止する。製作のみ確認済みなら送料未確認でも手配記録は可能。

標準導線は「手配を記録 → 確定費用を記録 → 未請求費目を選ぶ → 請求プレビュー → 請求書を確定」。請求済みを既定一覧から除外するが、履歴は残す。工場支払は手動実施の証跡であり、顧客請求済みや着金を意味しない。外部送金・実メール・carrier接続は実行しない。

## 保存・二重請求の契約

- 新roundは案件行lock内で採番し、要求UUIDとpayloadを恒久照合。同一要求再試行は同じround、別payloadは拒否。所属案件の商品/variant一致を検証。
- 概算は請求対象にしない。実費確認時に原通貨・金額・確認者/時刻・根拠と顧客負担を固定する。量産価格へ自動加算しない。
- 下書き選択だけでは請求済みにしない。確定時に対象費目をlockし、有効な請求割当がないことを原子検証する。請求番号・snapshot・費目割当は同一transaction。
- 取消は請求履歴を削除せず、スタッフの理由付き取消記録を追加する。有効な割当を解除した費目だけ再発行可能。再発行は新番号/版と旧版参照を持ち、旧PDFを保持する。取消後の古い要求UUIDの再試行で新請求を生まない。
- 送付受付・到達・顧客入金・工場支払は別記録。PDF再取得/再試行は発行snapshotを使い、最新為替で再計算しない。

## 候補の権限境界（SQL確定後に具体承認）

新台帳の直接INSERT/UPDATE/DELETE/TRUNCATEはauthenticatedへ付与しない。営業/管理者専用RPCで手配・費用確認・支払記録・請求確定/取消を行い、各要求を本人に限定して復帰する。工場/物流は現時点では新台帳操作なし。顧客への自社確定請求/PDF読取は新権限であり、既存保管請求承認から拡張を推定しない。匿名アクセス・Storage/Auth/default ACLの追加はこの設計に含めない。
