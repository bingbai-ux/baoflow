## 0. 憲法（違反は即失敗）

1. **STOP条件**: 想定外・曖昧・前提欠落・文書間の食い違い→その工程で止めて理由を報告し、**次に進める工程があれば順序を崩さず進む**（依存する工程はSTOPのまま残す）
2. **silent fallback禁止**
3. **検証なき完了なし**: 工程ごとの受け入れテスト全緑＋実行ログが、その工程を「完了」と呼ぶ唯一の条件。CLAUDE.md規定のbuild＋curl 200確認・カラム照合も毎工程実施
4. **デザインはF&C Design System完全準拠**（白文字・独自色・影・非ピル・外部UI/チャートライブラリ禁止）
5. **既存を壊さない**: `_archive`系・既存13ステップ画面・実データは削除/改変しない（D6移行を除く）。`npm run test`既存分は常に緑を維持
6. **先回り禁止の例外**: 本指示書は工程1〜9・横断・2-Mの一括発注である。この範囲内は連続実装してよい。範囲外（分析刷新・在庫刷新等）は禁止

## 1. 夜間運転の安全装置（最重要・違反は全成果無効）

| # | ルール |
|---|---|
| S1 | **実在の取引先・工場・配送業者へメール/通知を一切送らない**。DB内の既存client/factoryのメールアドレスをテスト送信に使うことも禁止。テストは本指示書§3で作るデモ取引先（宛先=白のメールアドレス）のみ。Resendの送信ログを成果物に含め、宛先が白のアドレス以外に存在しないことを機械確認する |

| S3 | **正直なステータス報告**: 朝の報告は工程別に「完了（テスト緑）/ 部分完了（何ができて何が残るか）/ STOP（理由）」の表を必ず含める。未完了を完了と書いた時点で全報告の信用を失う |

## 4. 各工程の実装とテスト

**要件の中身はすべて正本v1 §2（工程別要件）・§3（横断）・§4（裁定D1〜D8）を正とする。** ここでは工程ごとの合格条件のみ定める。全工程共通: F&C準拠のUI、スマホ幅(390px)で横はみ出しなし、操作後の通知（アプリ内＋メール）はデモ宛のみ。

### 工程1: シェル刷新＋プロジェクト作成（詳細は工程1指示書v1の§3〜§7をそのまま適用）
テスト: 工程1指示書のT1〜T8全部。

### 工程2: 商品登録
- クリック選択中心の商品追加（詳細→数量複数[スロット＋手入力]→配送方法[船/エア×工場手配/提携]→サンプル要否→食品検査要否→備考）
- 大/中/小分類・形状・素材・印刷色数・付属品（複数選択）を**設定>商品マスターで白が編集できる**こと（手動登録UI）
- サイズ: 縦×横×奥行／直径×高さ／kg指定／**空欄可**
- 商品名の自動付与・カード一覧・コピー・D&D並べ替え・ゴミ箱→確認ポップアップ
**テスト**: T2-1 選択肢だけで商品1件登録（自由入力ゼロ）／T2-2 サイズ空欄で登録可／T2-3 コピー→1項目だけ変更／T2-4 D&D順序がリロード後も保持／T2-5 削除確認ポップアップ／T2-6 マスター編集→選択肢に即反映

### 工程3: 顧客事前確認＋工場見積依頼
- 顧客確認メール（明細PDF＋リンク→内容ページ→「この内容で進める」ボタン。D2・ログイン不要）→BAOに通知→「工場に見積を依頼」解放
- 工場入力ページ（トークン・D5。既存external/rfq-responseを正本§2-③の項目に拡張）: 数量別単価USD・版代・色数追加費・特殊加工任意追加・送料3種・箱情報（サイズ/入数/重量）・日数5種（幅入力可）・備考・添付・**一時保存**→確定→BAO通知
**テスト**: T3-1 確認メールがデモ顧客（=白宛）に届きリンク承認が記録される／T3-2 リンクをGET（開くだけ）では承認されない（D2の実地）／T3-3 工場フォーム一時保存→再開→確定／T3-4 必須欠落は理由つきエラー

### 工程4: 価格提示・見積書・承認ループ
- 工場回答を表に反映→**提示価格⇄原価率の双方向計算**（%は1%刻み）→円換算で原価/総額/税込/想定利益表示
- 見積書PDF発行→デモ顧客へ送付→承認/差し戻し（理由付き）→差し戻しは第2回依頼として工程3へ戻るループ→**全版履歴の保存・展開表示**
**テスト**: T4-1 価格入力→率が自動計算、率入力→価格が自動計算（往復で値が一致）／T4-2 計算検証（既知入力の期待値表。円未満・税の端数含む）／T4-3 差し戻し→改訂→再提示でv1/v2の両方が履歴に残る／T4-4 承認で「請求書を発行」解放

### 工程5: 請求書・契約
- 発行日・振込期限選択→請求書PDF送付→顧客がリンク→内容確認→承認ボタン（D4: 日時＋操作記録を保存）→双方に成立通知→「入稿に進む」解放
**テスト**: T5-1 承認記録（誰が・いつ・どの書類か）がDBに不変保存／T5-2 承認前に入稿へ進めない／T5-3 請求書PDFの金額が工程4の確定額と一致

### 工程6: 入稿・前払い
- 双方向アップロード中継（顧客⇄工場・自動通知・D3: 既定素通し＋案件別「BAO確認を挟む」スイッチ＋BAO差し止め）
- 前払い（50%/30%選択）の振込記録→記録が無いと「製作開始」に進めない。**入金状態を案件ヘッダーで常時可視化**
**テスト**: T6-1 顧客アップ→工場（デモ）に通知→DL可／T6-2 スイッチONの案件ではBAO確認まで相手に通知が行かない／T6-3 前払い未記録で製作開始→理由つきで拒否

### 工程7: サンプル・本製造
- サンプルあり案件はサンプル工程を挟む（写真/動画アップ→顧客コメント→修正添付→本製造へ）。なし案件は直接本製造
- 製造中は納期逆算の「あと◯日」表示
**テスト**: T7-1 サンプルあり/なしで工程分岐／T7-2 写真動画アップ→顧客コメント→返信の往復／T7-3 残日数表示

### 工程8: 発送
- 工場の完了報告（写真/動画/備考）→BAO確認→**ラベルPDF自動生成**（工場DL可）→発送依頼→工場が梱包写真＋ラベル貼付写真を提出→追跡番号＋URL入力→発送完了→BAO・顧客通知→追跡リンク表示。食品検査日数の織り込み
**テスト**: T8-1 ラベルPDFに案件の配送先・商品・箱数が正しく載る／T8-2 梱包写真未提出で発送完了→拒否／T8-3 追跡番号入力→顧客画面（デモ）に反映

### 工程9: 検収・完了
- 到着→顧客通知→「受領」ボタン→納品書自動送付→案件完了→履歴として保存、リピート（案件コピー）の下敷き
**テスト**: T9-1 受領→納品書PDF送付→process_stage=9／T9-2 完了案件からリピート作成→商品仕様が引き継がれ工程1から開始

### 横断: チャット欄＋AI返信下書き
- 案件右側の開閉式トーク欄。外部とのメールやり取りをスレッド表示（送受信をdeal_communicationsに記録）。写真・ファイル投稿可
- 受信時に**AIが返信下書きを自動生成し下書き保存**（D7: Claude API最上位。コスト暴走防止に1通あたり生成1回＋手動再生成）
**テスト**: TC-1 デモ顧客からの返信メールがスレッドに表示／TC-2 下書きが自動生成され、編集→送信できる／TC-3 AI障害時は「下書き生成失敗・再試行」表示（silent fallback禁止）

### 2-M: カタログAI取込（最後・時間があれば）
- 正本§2-②-M。読取結果は**草稿→白の確認で確定**、原本PDF保存、低確信度は「要確認」空欄
**テスト**: TM-1 サンプルカタログ1冊→草稿カード生成→確認→商品マスター反映・工場タグ付与／TM-2 画像だけのページは「読み取り不可」明示
